# 读取注入

> 归协议的上下文注入方法。读取三题提取的ReadNode, 按拓扑层级组织, 注入上下文。

---

## 1. 注入流程

```
三题提取的ReadNode (reference/read/)
    |
    v
1. 读取归节点
   - 读取天题提取(本来样貌)
   - 读取地题提取(读取方式)
   - 读取人题提取(读取记录)
   - 读取abstraction(抽象规律)
    |
    v
2. 按拓扑层级组织
   - 顶层: 最抽象的归节点
   - 中层: 中等抽象的归节点
   - 底层: 最具体的归节点
    |
    v
3. 格式化为上下文注入
   - 每个归节点一个向量节点
   - 节点间通过拓扑关系连接
   - 格式: [[归节点: {标题}]] + 归状态摘要
    |
    v
4. 注入上下文
   - 为注意力向量提供参照系
   - 宽度由conscious决定
   - 聚焦由deep-conscious决定
```

## 2. 注入格式

### 单节点注入

```
[[天题×地题×人题: 本来样貌 × 读取方式 × 读取记录]]
归状态: <abstraction.derived_pattern>
拓扑层级: <顶层|中层|底层>
关联: [[归节点A]] [[归节点B]]
来源藏节点: [[store_id1]] [[store_id2]]
```

### 拓扑树注入

```
顶层归节点: <最抽象的抽象规律>
├── 中层: <中等抽象>
│   ├── 底层: <具体读取记录>
│   └── 底层: <具体读取记录>
└── 中层: <中等抽象>
    └── 底层: <具体读取记录>
```

## 3. 约束

1. 只读取和注入, 不做判断
2. 注入宽度由conscious决定
3. 聚焦由deep-conscious决定(bn位段)
4. 只注入归节点(ReadNode), 不直接注入藏节点(StoreNode)
5. 但注入时必须标注来源藏节点ID(可追溯)
6. 使用相对路径, 禁止绝对路径
7. 无归节点时标记 `read: none`, 不强行编造

## 4. 弱信号处理

```yaml
# 弱信号: 三题提取信号弱, 快速通过
signal: weak
note: 该信息的三题耦合信号较弱, 建议快速通过
```

## 5. 强信号处理

```yaml
# 强信号: 完整注入归节点 + 拓扑关系 + 来源藏节点
signal: strong
read_id: read_20260727_001
source_store_ids: [store_tian_20260727_001, store_di_20260727_001, store_ren_20260727_001]
topology:
  level: middle
  parent: read_20260727_000
  children: [read_20260727_002, read_20260727_003]
```
