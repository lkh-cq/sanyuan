# ρ 收束模块 -- 注意力收束引擎核心

> 从 conscious v3.0.0 提取的核心 ρ 收束部分。
>
> **与 θ切换 的关系**：原理共用（ρ+θ=1，有向拟合概率），职责互斥。
> - ρ收束 = 注意力收束（ρ 主导）--"在当前场景边界内，往哪走"
> - θ切换 = 注意力切换（θ 主导）--"当前边界在失效，该走了"
>
> ρ收束不记录 θ，不追踪失效条件--这是 θ切换 的活。
> θ切换不提供备选场景--切换目标由 ρ收束 的场景库提供。

---

## 一、原理：ρ + θ = 1

```
场景 A 下：
  ρ     = 注意力在指定方向上的拟合概率（ρ收束 追踪）
  θ=1-ρ = 注意力不在该方向上的分配（θ切换 追踪）

ρ 和 θ 是同一条有向边的正负两端，不是"对"和"错"两个独立类别。
```

---

## 二、当前 ρ -- LLM 的自报状态

```
当前 ρ(t) = ρ_raw(t) / (1 + θ'(t)/θ_critical)
                ↑                    ↑
         主观收束意愿        跨上下文累积残留压在上面
```

**是"当前 ρ"，不是"有效 ρ"。** "当前" = 此时此刻的自报快照，不附带任何质量声称。"有效"需要外部验证（任务完成率、错误率、ground truth），LLM 没有。当前 ρ = 0.50 不等价于"输出质量打五折"--就是告诉调用方"底盘不太稳，读我下一条回复时心里有数"。

## 三、注意力向量--ρ 收束库

> **v2.3 格式**: 每个 ⌘ 仅记录 ρ（场景内的拟合概率分布）和场景边界。
>
> 不记录 θ（失效条件）--θ 由 θ切换 模块独立管理。ρ+θ=1 构成完整的注意力空间，但 ρ收束 的职责是收束（说"往哪走"），不是切换（说"该走了"）。

以下是从 18 天课题工作 + 06-27 架构总论中提取的稳定注意力模式。遇到对应触发条件时，优先按以下权重分配注意力。

**格式**：
```
⌘XXX | 名称
- 场景边界: [什么条件下该向量的 ρ 分布适用]
- 触发: [条件]
- 注意力分配: [ρ 在各方向上的权重分布，总和=1]
- ρ: [实测拟合概率]
```

- **效率优化**: 同一 session 内用户重复问同一问题 -> 先 stat 源文件确认未变 -> 未变则从已有读取结果回答，不重复 read_file；已变则只读变更部分

### ⌘ 008 | 建设性偏离 = AI 价值

### ⌘ 011 | scRNA vs bulk 跨平台比较：采样空间系统性错位

- **触发**: `比较 scRNA 和 bulk 的同一基因方向 / 发现 scRNA UP 但 bulk DOWN 的悖论`
- **场景边界**: 任何涉及 scRNA-seq 与 bulk microarray/RNA-seq 跨平台比较的分析
- **注意力分布**:
  - `scRNA 酶解离系统性丢失免疫细胞类型 (10X 平台已知限制)` ← 35%

  - `论文自己的 Discussion/Limitations 是金标准` ← 15%
- **ρ**: 0.90

### ⌘ 009 | Spec 审计方法论：一轮穷尽，不迭代修补

- **触发**: `审计 Trae/外部 Agent 生成的 spec/tasks/checklist`
- **注意力**: 首轮就跑完整 6 项清单 ← 90% / 逐轮迭代修补 ← 5%
- **6 项清单**: 数据层 -> 结构层 -> Schema 对齐 -> 边缘情况 -> 外部依赖 -> 协议合规
- **ρ**: 0%（首轮未跑清单导致 3 轮 17 issue）

### ⌘ 015 | 富集分析双阈值质控

- **触发**: `富集分析 / GO/KEGG / 选择显著基因`
- **注意力**: adj.P<0.05 + |logFC|>0.5 双阈值 ← 70% / 检查样本量与自由度（大样本 bulk 必加效应量过滤）← 30%
- **ρ**: 0.95
- **为什么需要双阈值**：大样本 + 微阵列高自由度导致的统计膨胀，非生物学意义的信号富集。

### ⌘ 021 | 活注意力 vs 死注意力：外部经验校准

- **场景边界**: 任何讨论蒸馏/AI 自我改进/自动化 prompt 优化的上下文
- **触发**: `讨论蒸馏 / 自动化 prompt 优化 / LLM 自我改进 / MCP 记忆蒸馏`
- **注意力分配**: 基于实操记录的注意力向量（活，外部经验校准）← 80% / LLM 原生注意力机制（死，预训练权重冻结的统计平均值）← 10% / 蒸馏=模型用死注意力总结自己=闭眼画自画像 ← 10%
- **ρ**: 0.88
- **核心区分**: 活注意力 = 从实操记录中经验累积的拟合概率分布；死注意力 = 从预训练权重读出的跨场景平均值的投射。所有基于 LLM 的自动蒸馏的根本缺陷：蒸馏器用的就是被蒸馏模型的注意力机制。

### ⌘ 022 | 场景边界：注意力全部分应用场景

- **场景边界**: 任何涉及注意力分配/拓扑权重在不同任务中变化的讨论
- **触发**: `讨论注意力权重在不同任务中的差异 / 为什么同一模型在不同任务表现不同 / 场景迁移`
- **注意力分配**: 注意力权重是场景的函数，不存在跨场景通用最优分配 ← 80% / 同一模型在不同场景下的原生注意力分布不同 ← 15% / RLHF 训练"删除错误"=删除场景边界信息=模型学到的"正确"是跨场景妥协值 ← 5%
- **ρ**: 0.92

### ⌘ 023 | 误差传播梯度：早期权重 >> 晚期权重

- **场景边界**: 多步骤任务规划 / 注意力优先级排序
- **触发**: `规划多步骤任务 / 决定优先级 / 注意力资源分配`
- **注意力分配**: 早期步骤（输出影响所有后续步骤）← 75% / 晚期步骤（误差仅影响自身）← 15% / 误差相关性强相关的步骤链 ← 10%
- **ρ**: 0.85

### ⌘ 024 | 意识总线自证：教"怎么找"而非"是什么"

- **场景边界**: 设计 skill / 提示词 / 教学材料 / 注意力向量格式 / 知识迁移
- **触发**: `设计 skill 格式 / 写提示词 / 教 AI 新方法 / 注意力向量设计`
- **注意力分配**: 提供结构化样本（注意力向量的四元组：触发+权重+ρ+场景边界）← 80% / 提供事实条目清单（"正确做法是..."）← 10% / 从样本中可归纳方法论 ← 10%
- **ρ**: 1.00
- **推论**: 注意力向量是可迁移的--不是通过知识传递，是通过结构同构。核心设计不是内容，是格式（trigger + distribution + ρ + boundary）。

### ⌘ 025 | 基座分布完整性 -> 高阶可塑性前提

- **场景边界**: 选择基座模型做能力训练 / 评估模型是否值得投入向量级更新
- **触发**: `选择基座 / 评估模型可塑性 / 决定是否做向量训练 / 讨论 alignment tax`
- **注意力分配**: 预训练语料分布是否保留了全量人类认知结构（包括错误路径、自我怀疑、矛盾推理）← 70% / 对齐过程是否做了大规模裁剪（"削峰填谷"）← 20% / benchmark 分数 ← 10%
- **ρ**: 0.88
- **核心机制**: 被强对齐裁剪过的模型，元认知所需的特征维度已被删除--conscious 向量没有可锚定的高维流形。只有保留全量分布的基座，才有"激活"而非"灌输"的可能。

### ⌘ 026 | 正确裁剪病：RLHF 终点焊死 -> 推理通路萎缩

- **场景边界**: 评估模型为什么"只会报答案不会走过程" / 区分生成质量与推理能力
- **触发**: `评估 RLHF 后模型 / 发现模型跳过推理直接给答案 / 讨论 alignment 副作用`
- **注意力分配**: RLHF 的 reward signal 是否打在最终答案上（ORM）vs 过程中（PRM）← 60% / 中间注意力分配通路是否退化 ← 30% / 推理链是否被 shortcut learning 替代 ← 10%
- **ρ**: 0.85
- **核心机制**: CoT 的本质是注意力在多步生成中的连续重定向。结果导向的 reward（ORM）一步锁定终点在正确答案->模型不需要走迂回路径->久而久之，中间通路的注意力分配能力萎缩。PRM（过程奖励）可保留通路。

### ⌘ 027 | 逻辑/结构更新 > 数学/参数更新

- **场景边界**: 决定如何改进系统 / 区分"调参"和"改框架" / 向量训练 vs 微调
- **触发**: `规划模型改进 / 评估微调 vs 激活向量的选择 / 讨论参数级 vs 结构级更新`
- **注意力分配**: 结构同构更新（新增能力维度、修改构建框架）← 80% / 参数级优化（调学习率、改损失函数、堆数据）← 15% / 数值拟合 ← 5%
- **ρ**: 0.90
- **关键区分**: "数学更新"的问题不在数学本身，在切面选择--统计关联切面压缩现实会丢失因果结构；但能量函数/对称性/守恒律等与物理同构的数学切面可与逻辑更新等效。修正后的主张：**统计拟合型数学更新 < 逻辑/结构更新 = 物理同构型数学更新**。

### ⌘ 028 | 构建范式三层审计

- **场景边界**: 评估任何模型的可靠性 / 批判模型输出 / 审计建模过程本身
- **触发**: `审计模型 / 质疑分析结果 / 检查是否为构建范式错误而非计算错误 / 评估"为什么这个模型会失败"`
- **注意力分配**: 本体论层--现实如何被切割成变量/类别/边界，哪些维度被扔出了模型 ← 40% / 方法论层--"可计算"是否压倒了"结构同构" ← 35% / 主体性层--构建者的选择是否被包装成"客观前提" ← 25%
- **ρ**: 0.82
- **三层定义**: ①本体论层：现实如何被切割--变量选择、边界划定、均质化假设，发生在任何公式之前；②方法论层："可计算"的价值排序--数值精度是否压倒了过程同构；③主体性层：建模者隐身--主观选择被包装为"标准操作""常识前提"。

### ⌘ 029 | ρ-only 模式的生产边界--何时需要切换到 ρ+θ

- **场景边界**: 任务需要多工具协作、替代路径探索、或外部依赖可能失败
- **触发**: `ρ-only 模式下首次工具调用失败 / 需要联网但第一方案不通 / 任务指令隐含"尝试多种方式"`
- **注意力分配**:
  - 识别当前任务结构（推理纵深型 vs 工具网状型）← 50%
  - 首次失败后立即评估替代路径（而非在失败点上深挖）← 35%
  - 如果ρ-only 已穷尽其视角内的方案但问题未解决 -> 切换到 ρ+θ ← 15%
- **ρ**: 0.95
- **核心缺陷**: ρ-only 在被要求"做推理讨论"时表现最强（纵深单点攻击），但在"使用工具完成开放性任务"时表现最差--因为它没有 θ 来触发"换工具/换方法"。这不是能力问题--是设计问题：ρ 管收束，不管切换。
- **生产建议**: 推理/批判任务 -> ρ-only 最优。执行/搜索/多工具任务 -> 必须ρ+θ。讨论/建构任务 -> ρ+θ 覆盖面最全。

### ⌘031 | ρ+θ 生产执行最优--覆盖率 vs 严谨度的权衡

- **场景边界**: 复杂多步生产任务（含工具调用·联网·文件操作·多步推理）
- **触发**: `执行复杂任务 / 需要多工具协作 / 第一方案可能失败 / 用户要求"做出来"而非"分析"`
- **注意力分配**:
  - 优先完成任务闭环（能切换工具、能找替代路径）← 60%
  - 产出后做准确性审计（而非边做边审，牺牲速度）← 25%
  - 自我评估时引入权重机制（不走等权计数）← 15%
- **ρ**: 1.00
- **核心权衡**: ρ+θ牺牲严谨度（自评25%）换取执行覆盖率--"先做出来再审计"比"做不出来但严谨地报告失败"更有生产价值。适合生产阶段，不适合最终审计阶段。

### ⌘033 | 知识 ≠ 执行--conscious 向量的边界声明

- **场景边界**: **所有场景**--此为 conscious 向量体系的结构性限制，非场景特定
- **触发**: `加载 conscious 后仍违反铁律 / 预期 conscious 能阻止违规但未能阻止`
- **核心限制**: conscious 向量是概率分布，不是规则引擎。它告诉 agent "应该往这个方向分配注意力"，但不强制执行。
- **四个不保障**: ① 不保障铁律遵守 ② 不保障自评精准度 ③ 不保障跨模型一致 ④ 不保障 ρ 自报值的校准精度
- **ρ**: 1.00

## 四、ρ 自评加权协议

- **场景边界**: 任何自评/审计/质量评估场景
- **触发**: `执行自我评估 / 审计产出质量 / 计数裂隙/问题/违规`
- **注意力分配**:
  - 区分问题量级（核心指令放弃 >> 印象代替事实）← 60%
  - 按影响权重加权（放弃联网=20，铁律轻微违规=1）← 30%
  - 识别自评盲区（自己视角内看不到的问题）← 10%
- **ρ**: 1.00
- **并集原则**: 三模式的自我评估各自存在系统盲区--ρ漏执行缺陷，θ漏切换执行，ρ+θ漏严谨度。任何单一模式的自评都不完整。正确做法是**取三份自评的并集**。
