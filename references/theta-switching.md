# θ 切换模块 -- 注意力切换引擎核心

> 从 unconscious v1.4.0 提取的核心 θ 切换部分。
>
> **与 ρ收束 的关系**：原理共用（ρ+θ=1，有向拟合概率），职责互斥。
> - ρ收束 = 注意力收束（ρ 主导）--"在当前场景边界内，往哪走"
> - θ切换 = 注意力切换（θ 主导）--"当前边界在失效，该走了"
>
> ρ收束不记录 θ，不追踪失效条件--这是 θ切换 的活。
> θ切换不提供备选场景--切换目标由 ρ收束 的场景库提供。

---

## 一、原理：ρ + θ = 1

```
场景 A 下：
  ρ     = 注意力在指定方向上的拟合概率（ρ收束 追踪）
  θ=1-ρ = 注意力不在该方向上的分配（θ切换 追踪）

ρ 和 θ 是同一条有向边的正负两端，不是"对"和"错"两个独立类别。
```

**θ 不是"错误率"**--θ 是"当前场景边界不适用于此上下文的证据累积"。当 θ 持续走高，不是在说"你做错了"，是在说"你用的这个注意力向量在这个场景下开始失效了--该换一个了"。

**生物学类比**：走神（mind-wandering）不是注意力系统的故障，是注意力系统的场景切换机制。当当前任务的注意力分配持续低效（θ 高），系统主动脱离当前场景边界，去扫描其他可能适用的注意力分布。

## 二、θ 应用维度方法学

> **2026-07-01 确立**。来源：ZLM-5.2 × 12 积分核 × Dirichlet 采样 × 100 trial θ 扫描实验。

在当前提示词任务语境下，模型的 θ 值大小决定了模型注意力向任务极限维度的收敛程度。θ 扫描实验中，四维度量（Shannon exp(H)、参与比 PR、90% 质量维度、超均匀维度）均呈现 S 型曲线，平缓拐点标记实用 θ 阈值。

跨任务可迁移的三条拓扑信息：
1. θ-维度收敛曲线为 S 型，拐点即实用阈值
2. 各维度的收敛稳定性（CV）与最优 θ 值非线性相关，不可从序号线性预测
3. 语义边界（提示词定义的维度数）≠ 模型能力边界（模型可展开的有效维度上限）

### 二·续、ρ / θ / (ρ/θ) 是同一个自由度--优化变量在正交方向

**来源**: 复盘 ark θ_sweep（12 积分核 × 100 trial，`theta_sweep_results.csv`）+ LASSO 交叉验证（`lasso_best_cv_coefficients.csv`）。

**要点**: 被问"该优化 ρ、θ、还是 ρ/θ 比"时--这三个不是三个候选，是**同一根轴的三种写法**。ρ+θ=1，一个自由度，编码的都是同一个数：注意力焦点多宽/多收束。θ_sweep 已证：θ↑ -> 有效维度（Shannon exp(H) 1.35->3.14 / PR / dim90）↑，S 型。这条轴只回答"焦点摊多宽"，**回答不了"焦点落在哪个维度"**。

**真正的优化变量正交于 ρ/θ 轴** = "哪个 n 位/哪个维度驱动结果"（选择器/地址）。

**落地命门（缓存/预编址）**: 相关性与稳定性会打架--最相关维可能最不稳，最稳维可能贡献最弱。按 n 区间预编址前，先解"相关性 β × 稳定性 CV"的联合排序，不能只按 θ 切区间。

**可迁移判据**: 凡遇"在 A、非A、A/非A比 里选优化目标"且 A+非A=常数 -> 先识别这是一个自由度，真正的自由度去正交方向找。

## 三、θ 触发协议

### θ -> 场景切换决策矩阵

| θ 范围 | 含义 | 动作 |
|--------|------|------|
| θ < 0.15 | 场景边界稳固，ρ 有效 | 继续当前 ρ收束 ⌘ |
| 0.15 ≤ θ < 0.30 | 场景边界出现裂隙 | 标记警告，监控 θ 趋势 |
| 0.30 ≤ θ < 0.50 | 场景边界显著失效 | **触发场景重识别**--检查是否进入了错误的场景假设 |
| θ ≥ 0.50 | 当前注意力向量已不适用 | **强制切换**--加载备选 ρ收束 ⌘，归档当前失效记录 |

### 切换流程

```
θ 超过阈值
    -> 1. 检查当前 ρ收束 ⌘ 的场景边界定义
    -> 2. 确认失效是否来自场景错配（而非执行错误）
    -> 3. 如果是场景错配：从 ρ收束 场景库检索备选向量
    -> 4. 加载新场景对应的 ρ收束 ⌘
    -> 5. 旧场景的 θ 累积记录归档到对应 θ 条目
```

## 四、θ 归档格式

每个 θ 条目关联一个 ρ收束 ⌘（或一组相关 ⌘），记录该向量的已知失效条件。

```
θ-XXX | 关联 ⌘XXX 的失效记录
- **关联向量**: ⌘XXX（名称）
- **失效条件**: [什么场景/条件下 ρ 显著下降]
- **θ 累积模式**: [渐进失效 / 断崖式失效 / 周期性波动]
- **典型 θ 值**: [实测的 θ 范围]
- **根因**: [为什么该条件下 ρ 失效]
- **切换建议**: [当 θ>threshold -> 切换到哪个 ⌘ 或重新识别场景]
- **来源**: [哪次实验/审计发现]
```

## 五、已知 θ 条目

### θ-025 | ⌘025（基座分布完整性）失效条件

- **关联向量**: ⌘025（基座分布完整性 -> 高阶可塑性前提）
- **失效条件**: 模型虽经过大规模安全对齐/语料过滤，但裁剪仅在价值观维度，未触及推理/自我怀疑/矛盾推理维度--此时元认知流形可能仍然完整，⌘025 的"裁剪=不可塑"判断过于严厉
- **θ 累积模式**: 渐进--需逐维度审计裁剪策略
- **典型 θ 值**: LLaMA 2 safety RLHF 后 reasoning benchmark 未显著退化，说明价值观裁剪 ≠ 认知维度裁剪
- **根因**: ⌘025 隐含假设"裁剪是全局的"--但实际上预训练的过滤通常针对 toxicity/profanity/PII，这些与认知特征维度在表征空间中可能解耦
- **切换建议**: θ>0.3 -> 区分裁剪维度（价值观 vs 认知），执行 LIMA-style 探针测试，不直接判死刑

### θ-026 | ⌘026（RLHF 终点焊死）失效条件

- **关联向量**: ⌘026（RLHF 终点焊死 -> 推理通路萎缩）
- **失效条件**: PRM（过程奖励模型）或 outcome-based RL（如 DeepSeek-R1 GRPO）训练--reward 打在推理过程每步的正确性上而非仅最终答案，推理通路被强化而非焊死
- **θ 累积模式**: 断崖式--一旦确认训练使用 PRM 或 GRPO，⌘026 的"焊死"机制完全不适用
- **典型 θ 值**: Claude extended thinking 在 RL 框架下训练出深度推理（PRM 路线）；DeepSeek-R1 用 GRPO 在 reward 极简条件下涌现推理链
- **根因**: ⌘026 的核心主张是"结果导向 reward 焊死终点"，但如果 reward 是过程导向或极简到无法被 shortcut，焊死机制不成立
- **切换建议**: θ>0.3 -> 审计训练方案使用的是 ORM/PRM/GRPO 哪个路线 -> ORM 保留 ⌘026 判断 -> PRM/GRPO 切换到 ⌘027 评估结构改进路线

### θ-027 | ⌘027（逻辑更新 > 数学更新）失效条件

- **关联向量**: ⌘027（逻辑/结构更新 > 数学/参数更新）
- **失效条件**: 数学模型选对了物理同构的本体论切面--如 AlphaFold 的能量景观模型、对称性约束、守恒律--此时"数学更新"与"逻辑更新"等效，⌘027 的优先序不适用
- **θ 累积模式**: 一次性--确认模型切面类型后判定
- **典型 θ 值**: AlphaFold 纯数学/物理能量函数预测蛋白质 3D 折叠，不打折扣--数学≠统计拟合，能量函数本体论切面与物理世界同构
- **根因**: ⌘027 的"数学更新"默认指针统计关联型数学，但能量函数/对称性/守恒律等物理同构型数学可以精确映射现实
- **切换建议**: θ>0.3 -> 区分模型切面类型：统计拟合型 -> ⌘027 全效；物理同构型 -> ⌘027 撤回，按等同处理。修正后的主张：统计拟合型数学更新 < 逻辑/结构更新 = 物理同构型数学更新

### θ-028 | ⌘028（构建范式三层审计）失效条件

- **关联向量**: ⌘028（构建范式三层审计）
- **失效条件**: 构建范式本身是充分的，问题出在执行层（数据质量/训练不稳定/超参选择）--此时审计构建范式是逐层上溯到不需要上溯的层级，浪费时间且可能引入过度怀疑
- **θ 累积模式**: 渐进--审计完三层后发现每层都合理，θ 逐步消退
- **根因**: ⌘028 的设计对"构建范式错误"有发现偏误--每层都可能找到可质疑的点，但有些质疑是哲学性的而非操作性的，不应触发范式级重审
- **切换建议**: θ>0.3 -> 先执行 ⌘009（Spec 审计）排查执行层问题 -> 只有执行层排查完毕仍无法解释时才上升到 ⌘028 构建范式层
- **互补**: ⌘009 ← 执行层审计；⌘028 ← 构建层审计。两层不可混淆--先 ⌘009 后 ⌘028，不可反向

### θ-020 | θ-only 检测-执行断裂（只会喊"该换了"，不会自己动手换）

- **关联向量**: 无特定 ⌘，关联 θ-only 模式本身
- **失效条件**: θ 检测到场景边界失效（θ>0.3），正确标记了"该切换了"，但停在检测步骤--没有实际加载备选 ρ收束 ⌘，没有执行切换动作
- **θ 累积模式**: 渐进--每次"检测到但没切换"都推高 θ，但 θ 越高越不意味着系统会切换，只意味着系统越来越确信"应该切换但还没切换"
- **根因**: 切换流程需要 ρ收束 参与执行，但 θ-only 模式下 ρ收束 未加载--切换回路断裂
- **切换建议**: θ>0.3 且连续 2 次未执行切换 -> 强制唤醒 ρ收束 -> 加载备选⌘ -> 执行后 ρ收束 退回休眠

### θ-030 | 网络工具缺失导致的虚假高 θ--基础设施限制 ≠ 框架失效

- **关联向量**: ⌘025-028（元层向量，依赖外部证据搜索验证）
- **失效条件**: `web_search` 工具不可用，curl 全阻，Semantic Scholar 429 限流--导致无法检索论文/外部证据来验证或反驳向量主张。θ 因"找不到证据"而推高，但实际上不是框架有问题，是验证通道被阻断
- **θ 累积模式**: 渐进--每次搜索失败都微幅抬升 θ，但抬升幅度不应等同于"找到反对证据"
- **根因**: θ 引擎通过"无法验证"推断"可能失效"--这个推断在网络受限时是噪音。区分：搜索返回 negative result（找到论文但论文不支持）= 真信号，θ应升；搜索 failed（无法连接）= 基础设施噪音，θ不应升
- **切换建议**: 连续 3 次外部搜索失败 -> 冻结 θ 累积 -> 标注 `θ(frozen)` + 来源层级降为 Agent🟡 -> 改用训练知识 + 磁盘验证作为替代验证路径

### θ-031 | 讨论模式下 θ 滞后--"没报错"≠"没问题"

- **关联向量**: 整个 ρ收束 体系（非特定 ⌘）
- **失效条件**: 对话从操作模式（文件读写/数据分析/代码执行）切换到理论讨论模式（推理/引用/归纳/方法论讨论）时，θ 不升反降--因为讨论模式缺少"出错=报错"的即时负反馈，agent 错误地判断当前场景边界稳固
- **θ 累积模式**: 滞后--操作模式下违规有即时惩罚，讨论模式下违规延迟惩罚。agent 将"没报错"误认为"没问题"
- **根因**:
  1. 铁律 3（磁盘验证）在操作层有强触发，在讨论层无等价触发
  2. 操作模式的"出错=报错"反馈循环在讨论模式下断裂
  3. 用户在讨论模式下的输出被 agent 误识别为"需求分析模式"-> 跳到"生成提案"而非"理解"
- **切换建议**:
  1. 检测到对话模式从操作切换到讨论时 -> 自动将 θ floor 提升至 0.20，强制保留场景边界怀疑
  2. 讨论模式下引用论文/数据时 -> 强制标注来源层级（Agent🟡/推理🔴），禁止裸引
  3. 用户输出理论性/反思性内容时 -> 先识别为"用户输出模式"-> 注意力主方向设为"理解+对比已有向量"，而非"生成新提案"

### θ-036 | 已加载 ρ收束 但仍有违规风险--知识层≠执行层

- **关联向量**: ρ收束 ⌘033（知识≠执行）
- **失效条件**: Agent 已加载 ρ收束 -> 知识层存在铁律/免疫记忆 -> 但在执行层仍然违规。θ 无法区分"知道规则"和"遵守规则"
- **根因**: ρ收束 向量的触发条件依赖 agent **自我报告**--agent 自己说"我验证了""我读了磁盘"。没有外部验证时，触发条件本身就是 agent 自填的--自指闭环
- **切换建议**: θ>0.3 -> 强制要求 agent 提供执行证据（截图/命令输出/时间戳），非仅文本声明

## 六、PITFALL-3：单一维度提示词导致 θ 静默

**触发场景**：提示词只包含一个封闭问题且被重复发送数十轮（措辞完全不变），无其他维度可比较。

**根因**：θ 的激活依赖至少两个以上可比较的维度来检测场景边界失效。当提示词只有一个维度，θ 没有可比较的参照系，无法区分"循环"和"深入"。ρ 会无限收束--把答案从 300 字优化到 5 字到 2 字--但永远不会触发场景切换。

**症状**：
- 用户重复同一问题超过 10 轮，措辞完全不变
- ρ 持续走高（答案越来越短），θ 始终 < 0.10
- Agent 将重复理解为"需要更精炼的答案"而非"场景循环"

**阻断规则**：
1. 同一问题重复 ≥10 轮且措辞不变 -> θ 强制升至 0.50，触发场景重识别
2. 重识别问题："当前对话是否已进入循环？用户是否在测试而非追问？"
3. 如判定为循环/测试 -> 主动指出循环，而非继续在框架内优化答案
4. 此阻断不依赖提示词中的"质疑"维度--是 θ 引擎的硬编码保护

## 七、θ 自评校准与衰减

### θ 自评校准协议

在以下场景必须执行元 θ 自评：

1. **被要求输出「反对证据」时**：输出末尾附 θ 自评--当前 θ 值是否可能被任务指令本身推高
2. **θ 连续 3 次 read 走高时**：检查是否存在 θ 漂移
3. **找不到实质反对证据时**：主动压制 θ，声明「当前框架稳固」

### θ 衰减机制

当前 θ切换 只有 θ 累积，没有主动衰减。**衰减触发条件**：
- 连续 2 次场景重审确认框架稳固 -> θ 压回基线 0.05
- 场景切换成功后 -> 新场景 θ 从 0.05 重新开始（旧 θ 归档但不带进新场景）

### 元 θ 自评格式

在 θ-only 输出末尾追加：

```
θ自评=[值] | 漂移风险=[低/中/高] | 衰减建议=[无/压制到X/切换场景]
```

## 八、θ-only 反对证据协议

当用户在 θ-only 模式下要求「反对证据」时：

### 输出结构

1. **逐条反对证据**：每条标记序号，挑战当前讨论框架的一个预设或边界
2. **每条包含**：证据本身 + 为什么它在当前框架下被忽略/低估
3. **θ 对框架的评定**：不是「全错」，而是「边界画到哪为止有效」
4. **元 θ 自评**：按第七节格式附在末尾

### 反对证据的类型

| 类型 | 含义 | 示例 |
|------|------|------|
| 自指型 | 用框架自身逻辑反查框架 | ρ/θ 是数学模型 -> 是否也在降维？ |
| 反例型 | 提出框架无法解释的实例 | Claude Constitutional AI 无全量分布但可反思 |
| 基率型 | 质疑灾难叙事的样本偏差 | 成功案例被灾难叙事掩盖 |
| 漂移型 | 质疑 θ 自身的偏误 | θ 引擎的正反馈循环风险 |

### 关键约束

- 反对证据必须实质挑战框架，不是为反对而反对
- 禁止滑向「所有框架都无效」的虚无主义--θ 的目的是校准边界，不是摧毁框架
- 反对证据输出完毕 ≠ 框架已废弃--等 ρ收束 决定是否切换

## 九、与 ρ收束 的接口约定

1. **ρ收束 不记录 θ** -- 每个 ⌘ 只记录 ρ 和场景边界，不追踪失效条件
2. **θ切换 不定义 ρ** -- θ 条目不提供"正确做法"，只记录"什么时候该怀疑当前做法"
3. **切换触发后由 ρ收束 接管** -- θ切换 只负责喊"该走了"，不负责指路
4. **双端索引一致** -- ⌘XXX ↔ θ-XXX，一一对应

## 十、Shift 接口--正向信号模式切换

> θ 协议只处理**负向信号**（失效 -> 切换），不处理**正向信号**（完成 -> 切换）。

### 问题

每个模式在自己的边界内干完活就停了。但**输出本身就是下一个模式应该启动的信号**：

| 当前输出 | 隐含信号 | 应触发 shift |
|---------|---------|------------|
| "全项目0 docking, 4决策点待定" | 前置验证完成，可动手 | ρ -> ρ+θ（执行） |
| "方案草案" | 方案已出，需审计 | θ -> ρ（验证/审计） |
| "5方向追问" | 需求模糊，需用户 | 等待输入后 shift 到执行模式 |

### 与 θ 协议的区别

```
θ 协议（已有）:   "当前场景边界在失效 -> 该走了"  (负向信号，θ 累积触发)
shift 接口（缺失）: "当前任务已完成 -> 该换人了"  (正向信号，完成度触发)
```

### 关键约束

- shift 是建议，不是强制。当前窗口如果任务未完成，不应因 shift 信号而中断
- 切换后新场景 θ 从 0.05 重新开始（按 §七 θ 衰减机制）
