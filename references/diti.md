# 地题_读取方式

> 地题 = 读取方式。不是"条件/边界层提问", 是读取信息使用的方法、路径、媒介、工具、过滤条件。
> 地居天与人之间, 管理信息的流与止。

## 提取协议

### 提取问题
1. 用什么方法读取(观察/实验/文献/数据挖掘/化学分析)?
2. 使用什么工具(显微镜/光谱仪/数据库/搜索引擎)?
3. 读取路径是什么(直接观察/间接引用/跨域查询)?
4. 有什么过滤条件(语言/年代/来源/置信度/学科)?
5. 读取范围是什么(全量/抽样/特定维度)?
6. 读取过程中有什么信息损失风险?

### 输出格式

```yaml
diti:
  method: <读取方法>
  tool: <工具/媒介>
  path: <读取路径>
  filter: <过滤条件>
  scope: <读取范围>
  loss_risk: <信息损失风险>
```

### 示例

对象: 唐三彩钴蓝釉陶俑(藏节点)

```yaml
diti:
  method: 考古类型学+化学成分分析
  tool: X射线荧光光谱仪(XRF)+文献比对
  path: 实物检测->成分数据->文献交叉验证
  filter: 年代=唐代, 地域=长安/洛阳窑系, 釉色=钴蓝
  scope: 釉料成分+胎体工艺+纹样类型
  loss_risk: XRF表面检测可能遗漏釉层内部成分; 文献记录可能有朝代偏好性
```

### 边界

地题只记录读取方式, 不记录:
- 信息的本来样貌(属于天题)
- 读取者的解释(属于人题)
- 读取方式本身不携带固有方向(方向只在FlowEvent中)

### 冻结约束

1. 地题不是"条件/边界", 是"读取方式"
2. 地居天与人之间, 读取必须经由地(方法/工具/路径)
3. 不默认存在绕过地题的天题->人题直连
4. 地题本身不携带固有方向
