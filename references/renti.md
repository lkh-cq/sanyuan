# 人题_读取记录

> 人题 = 读取记录。不是"实践层提问", 是读取者形成的解释、摘要、模型、假说、争议和应用记录。

## 提取协议

### 提取问题
1. 读取者是谁(研究者/agent/历史学者)?
2. 读取后形成了什么记录(摘要/数据表/分析报告)?
3. 解释是什么(对信息的理解)?
4. 有什么假说(基于读取提出的推断)?
5. 存在什么争议(不同读取者的分歧)?
6. 有什么应用记录(读取结论被如何使用)?

### 输出格式

```yaml
renti:
  reader: <读取者>
  reading_record: <读取形成的记录>
  interpretation: <解释>
  hypothesis: <假说>
  disagreement: <争议>
```

### 示例

对象: 唐三彩钴蓝釉陶俑(藏节点)

```yaml
renti:
  reader: 考古研究者A + 化学分析者B
  reading_record: |
    1. 类型学记录: 唐三彩明器, 钴蓝釉, 造型为文吏俑
    2. XRF成分记录: CoO含量3.2%, PbO含量45%, SiO2含量35%
    3. 文献比对记录: 与《新唐书·地理志》记载的钴料进口记录吻合
  interpretation: |
    钴蓝釉陶俑是唐代丝路贸易的物证。钴矿来自波斯, 经丝路输入长安/洛阳窑场。
    低温铅釉技术在唐代已成熟, 钴蓝呈色需要精确控温。
  hypothesis: |
    钴蓝釉技术可能通过波斯陶工直接传入, 而非中国本土独立发现。
    理由: 唐代以前无钴蓝釉实物, 且钴矿产地锁定波斯。
  disagreement: |
    争议1: 部分学者认为钴料来自甘肃本土矿藏(但未找到同时代钴矿开采证据)
    争议2: 钴蓝技术传入路径(丝路陆运 vs 海路)
```

### 边界

人题只记录读取后的记录和解释, 不记录:
- 信息的本来样貌(属于天题)
- 读取方式(属于地题)
- 原始藏内容(人题是读取记录, 不是藏内容)
- 人题不得覆盖原始藏内容

### 冻结约束

1. 人题不是"实践/行为", 是"读取记录"
2. 人题产生的解释和假说属于归, 不属于藏
3. 人题结论进入下一轮藏时必须生成新节点, 不覆盖
