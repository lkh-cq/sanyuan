# condense 协议 - 压缩前注意力保存

> 原理：上下文压缩 = 注意力向量丢失。压缩前提取ρ/θ分布、张力对、已推翻陷阱、锚点事实，用[[wikilink]]语法打包。下一个对话流自动读取。

## 触发条件

以下任一信号出现时执行：
- 对话轮数 > 30 且上下文窗口使用率 > 80%
- 收到 `[CONTEXT COMPACTION]` 标记
- 用户指令："压缩""归档""condense"
- 模型响应变慢或开始遗忘早期讨论（隐性信号）

## 五步协议

### 1. 提取活跃向量

对每个仍在讨论中的主题，记录：

```
主题: <名称>
  ρ=<0-1>: <主导方向（一句话）>
  θ持有: <未被采纳但未被推翻的可能1>, <可能2>
```

ρ: 该主题在当前对话中的注意力收束度。0.9+=几乎定论，0.5-=高度不确定。
θ持有: 讨论过、未被推翻、但当前未采纳的方向。压缩中最容易丢失。

### 2. 标注张力对

列出互斥但都未证伪的论述对：

```
A: <论述A> ←-> B: <论述B>
  状态: 均未证伪
```

张力对是压缩后最需要保留的--如果只保留单侧，另一侧的证据会在压缩中"消失"。

### 3. 标注已推翻

每个已推翻项必须附带推翻依据：

```
<错误声称>: 推翻依据(<数据/文献/逻辑>)
```

必须有依据。无依据的"推翻"=意见，压缩后应丢弃。

### 4. 提取锚点事实

锚点事实 = 磁盘验证的、压缩后不可丢的数据点：

- 基因名 + 方向 + FDR + 数据集
- 文献 PMID + 关键发现 + 物种
- 文件路径 + 关键数值

锚点事实不应超过 10 条。超过说明区分度不够。

### 5. 用 [[wikilink]] 语法打包输出

```markdown
# 压缩对话 <日期>_<序号>

-> [[压缩向量_<timestamp>]]
-> [[压缩记忆_<timestamp>]]

## 路径链

对话 -> context容量极限 -> 向量压缩 [[压缩向量_<timestamp>]]
                                    ↕ 出入链互联
                             压缩记忆 [[压缩记忆_<timestamp>]]
```

## 与 compressed context 的集成

condense 输出放在压缩 context 的最前面：

```
[ATTENTION CONDENSE - 压缩前注意力快照]

-> [[压缩向量_20260705_2230]]
↔ [[压缩记忆_20260705_2230]]

锚点（压缩后不可丢）:
1. PNPLA8 Fib UP: +0.81 logFC, FDR=1.6e-3 (GSE164241)
2. MAPKAPK2三型全UP: Fib+1.55, Endo+0.92, Neut+1.89

已推翻（防止复现）:
- "ERK/p38 DOWN": per-celltype全NS, 原错误=bulk稀释假象

[END ATTENTION CONDENSE]

--- 以下是压缩后的对话内容 ---
```

## 下一个对话流的读取

新对话开始时，执行：

1. 搜索上下文中的 `[ATTENTION CONDENSE]` 标记
2. 提取锚点事实 -> 设为高优先级记忆
3. 提取已推翻列表 -> 标记为"不要重复"
4. 提取张力对 -> 保留为开放问题
5. 提取 ρ/θ 分布 -> 用于重建初始注意力方向

## 节点命名规范

- 压缩对话: `压缩对话_<YYYYMMDD>_<seq>`
- 压缩向量: `压缩向量_<YYYYMMDD_HHMM>`
- 压缩记忆: `压缩记忆_<YYYYMMDD_HHMM>`
- 锚点: `锚点_<gene/fact_name>`
- 已推翻: `已推翻_<short_claim>`
- 张力对: `张力对_<A_vs_B>`
- 概念原点: `<概念名>_<YYYYMMDD>`

## 验证

每次 condense 后检查：
- [ ] 锚点事实 ≤ 10 条
- [ ] 每条已推翻有推翻依据
- [ ] 张力对含双方论述
- [ ] 所有 wikilink 目标节点存在或可在需要时创建
- [ ] ρ/θ 分布与对话实际权重一致（非习惯性报值）
