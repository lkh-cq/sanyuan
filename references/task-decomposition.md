# 子任务拆分协议

> 复杂任务 -> 相互可验证的子任务 -> 独立产出 -> 合成取并集

---

## 协议

### 1. 识别总任务边界

明确任务的范围、深度、时间约束。

### 2. 拆成子任务

每个子任务拥有独立的:
- 输入
- 读取范围
- 三才藏节点 (StoreNode)
- 三题归节点 (ReadNode)
- ρ/θ 状态
- 完成条件

### 3. 子任务独立执行

子任务结果不得直接拼接。每个子任务独立产出耦合向量, 独立落盘。

### 4. 合成前检查

合成前必须检查:
- 定义是否一致 (三才/三题定义跨子任务一致)
- 时间范围是否一致
- 读取方式是否兼容
- 证据等级是否一致
- 是否存在冲突记录

### 5. 合成

合成结果必须保留每个子任务的来源链 (source_store_ids)。

## 与藏归的关系

```
复杂任务
    |
    v
子任务A: 藏A -> 归A -> 耦合向量A (独立落盘)
子任务B: 藏B -> 归B -> 耦合向量B (独立落盘)
子任务C: 藏C -> 归C -> 耦合向量C (独立落盘)
    |
    v
合成: 取并集(非串联)
    |
    v
检查: 定义一致性 + 时间范围 + 读取兼容 + 证据等级 + 冲突
    |
    v
合成结果 (保留来源链)
```

## 单节点故障原则

单个子任务故障不推翻全局。未完成的子任务标记为 `status: blocked`, 合成时跳过但保留占位。

## 与误差传播梯度的关系

早期子任务(输出影响所有后续步骤)的注意力权重 > 晚期子任务。按误差传播影响力加权分配注意力。
