# 读者端分析交付规范

## 核心原则

内部拓扑用于识别、比较和校验关系；读者端产物用于解释这些关系。两层必须分离。

| 层级 | 允许内容 | 默认是否展示 |
| --- | --- | --- |
| 内部推理层 | 节点、边、路径、编号、关系代码、`B_T/M_T/H_T/Z_T`、YAML 账本、证据压力和缺口标签 | 否 |
| 读者交付层 | 完整概念名称、段落级逻辑分析、证据边界、必要限制和可验证结论 | 是 |

内部可追溯不等于外部可读。不得把工作层的压缩表示直接复制为最终回答。

## 默认成文单位

文献精读、全文解析或写作逻辑分析以“一个完整论述单元”为基本交付单位。一个单元通常写成 2—4 句，不机械对应一个内部节点：

1. **内容与顺序：**说明作者先提出什么，再引入什么。
2. **逻辑作用：**说明这一步与前文是承接、递进、转折、解释、限制、对照还是因果主张，并指出它把论述推进到哪里。
3. **证据边界：**说明关键证据实际支持到哪一步，是否存在因果、尺度、物种、方法、时间或空间跳跃。

如果一个段落只承担单一背景功能，可压缩为 1—2 句；如果存在多条独立证据链，应拆成多个论述单元，避免把所有关系塞进一个长句。

正文应以连续段落为主。标题可用于区分全文主线、章节分析和证据边界，但每个标题下仍应形成完整论述；项目符号只用于真正并列的材料、指标或待办项，不用于把“承接、递进、转折、解释”等关系逐条拆散。

## 从内部关系到自然语言

关系代码只能用于内部识别。交付时根据上下文改写为完整语义：

| 内部关系意图 | 读者端表达方式 |
| --- | --- |
| 前提 / 铺垫 | “作者先界定……，为后续讨论……提供前提。” |
| 承接 / 递进 | “在前述……基础上，本段进一步把问题推进到……。” |
| 转折 / 对照 | “与前述……不同，本段转而强调……，从而修正了原先的解释范围。” |
| 解释 / 机制 | “作者以……解释……；现有证据能够支持……，但尚不能确认……。” |
| 因果主张 | “作者据此提出……导致……的因果关系；该主张是否成立取决于……。” |
| 限定 / 边界 | “这一结论目前仅适用于……，不能直接外推至……。” |
| 拓扑断裂 | “从……推进到……时缺少……这一中间证据，因此论证在此发生跳跃。” |
| 缺席节点 | “鉴于作者提出……，通常还需要……验证，但文中未见该证据，因而结论应降级为……。” |

不要逐字替换关系标签。先理解该关系在当前段落和全文中的具体作用，再选择自然语言表达。

## 文献分析的推荐结构

按任务需要选择，不强制凑齐所有标题：

1. **全文论证主线：**用一段话说明研究问题如何被提出、证据如何展开、结论如何形成。
2. **段落或章节逻辑：**逐单元解释内容顺序、段内关系和段间推进。
3. **证据与结论：**说明主要结论分别依赖哪些结果，证据压力集中在哪里。
4. **断裂与缺席：**用完整句子解释缺少什么连接、为什么应当出现、如何影响解释。
5. **写作评价：**评价衔接、信息密度、概念转换和论证节奏，不把领域证据不足混写成单纯文风问题。

## 正反例

不得交付：

> 炎症 → 铁代谢紊乱 → 铁死亡 → 组织损伤；Figure 3 supports D4。

应交付：

> 该段先指出炎症伴随铁代谢紊乱，随后以脂质过氧化升高和 GPX4 下降，将论述进一步引向铁死亡。它承接前文的组织损伤表型，并尝试把现象解释推进到分子机制；但这些指标目前只能证明铁死亡相关变化与损伤同时出现，尚不足以确认铁死亡是组织损伤的直接原因。

## 图表与示意图

示意图不是默认交付。只有关系数量较多、顺序或分支仅靠短段落难以看清时才使用，并同时满足：

- 节点写完整名称，不只写缩写或编号；
- 边写明具体关系，不只画箭头；
- 给出必要图例、证据来源或正文位置；
- 图后用短段落解释读图方式和主要结论；
- 图不能替代正文分析，也不能展示无关的内部状态。

## 交付前检查

- 删除无解释的节点编号、关系代码、裸箭头和内部变量。
- 确认每段都能脱离内部 Schema 独立阅读。
- 确认主要逻辑分析形成连续段落，没有退化为“一种关系一个项目符号”。
- 确认逻辑关系由完整句子表达，而非标签堆叠。
- 确认事实、作者主张和分析者判断没有混成同一语气。
- 确认缺口说明包含“缺什么、为什么需要、影响什么”。
- 仅在用户明确要求审计时，把内部表示放在主要结果之后的独立附录中。
