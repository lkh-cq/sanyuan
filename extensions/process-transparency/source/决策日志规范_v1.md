# 决策日志规范 v1.0 (过程透明协议)

> 日期: 2026-08-07 | 来源: 反编译失败复盘 + 群聊讨论 (过程透明 > 信息准确)
> 背景: 反编译项目因"自圆其说反复翻转"污染知识库, 置信度标注无效。
> 根因: 只记录了结论, 没记录过程。本规范让决策自带时间线, 翻转可被精确检测。

---

## 一、为什么需要这个

- **置信度标注失败**: 事后给结论贴标签, 污染已在过程中发生
- **过程透明 > 信息准确** (吴港风微暖): 没有过程日志, 找不到问题点
- **翻转检测的前提**: 检测器需要结构化数据, 自由文本无法区分"讨论正反"和"时间线翻转"

## 二、核心格式: 决策条目

每个决策条目固定五行:

```markdown
### D-<编号> [YYYY-MM-DD] <决策主题>
- 结论: <可行 | 不可行 | 待验证 | 已废弃>
- 依据: <为什么这样判断 - 具体的证据/观测, 不是AI叙事>
- 假设: <未验证的前提 - 每一条都要写, 这是自圆其说的源头>
- 验证: <用什么方法验证这个假设 - 没有验证方法 = 叙事>
```

### 示例 (反编译案例)

```markdown
### D-01 [2026-08-01] 反编译SHP可行吗?
- 结论: 可行
- 依据: 初步搜索发现社区有SHP解包工具
- 假设: 该工具适用于目标游戏版本
- 验证: 下载工具, 对目标exe运行, 看输出

### D-02 [2026-08-02] 反编译SHP可行吗? (翻转!)
- 结论: 不可行
- 依据: D-01的验证失败 - 工具不认目标格式
- 假设: (无新假设)
- 验证: (D-01已验证, 关闭)
```

**翻转检测规则**: 同一主题 `D-01 可行 → D-02 不可行` = 一次翻转。累计2次翻转 → 系统警告"可能陷入自圆其说", 要求回到目标审计。

## 三、三问过滤 (每个决策前先问)

1. **这个方向本身对吗?** (目标审计) — 反编译SHP本身就是错的, 该在第0步被否掉
2. **这个结论能被验证吗?** (可证伪性) — 没有验证方法 = 叙事
3. **我记录依据了吗?** (过程透明) — 依据必须是观测/数据, 不是AI的连贯叙事

## 四、与现有体系的集成

- 位置: `workspace/<wf>/决策日志.md` (或追加到 02_progress.md 的决策段)
- 检测: daily_maintenance TASK6 扫描 `- 结论:` 字段, 同一主题状态变化 → 翻转预警
- 免疫: 已废弃条目进 `condense/overturned/` (已是现有机制)

## 五、为什么这次能防住反编译事故

| 事故点 | 旧做法 (失败) | 本规范 |
|--------|--------------|--------|
| 目标不明确 | AI默认"反编译可行"是任务 | 三问过滤第1问: 方向本身对吗 |
| 自圆其说 | AI每步编解释, 无记录 | 决策条目强制"依据+假设+验证" |
| 反复翻转 | 无检测, 直到污染 | 结构化状态字段 → TASK6自动预警 |
| 事后修补 | 标置信度 (无效) | 过程留痕 (有效) |

## 六、局限

- 规范依赖人/AI遵守格式, 不强制
- 词对检测仍是提示性 (无法语义判断), 真正的价值在结构化后
- 需要 habit 固化: 每次决策自动按格式记录
