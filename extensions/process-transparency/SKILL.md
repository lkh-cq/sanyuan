# 过程透明与决策防污染扩展

> 模块: extension-process-transparency
> 版本: 0.1.0 (experimental)
> 来源: 2026-08-07 反编译失败复盘 + 群聊讨论(过程透明 > 信息准确)
> 定位: 与 extension-archive-ingestion 互补——archive-ingestion 管"归档后方案如何进本体",
>       本扩展管"归档前决策如何记录防翻转"。

---

## 一、解决的问题

**自圆其说污染**: 探索性任务中, AI 生成"结构自洽、语义合理"的叙事, 每一步都自圆其说,
结论反复翻转(可行→不可行→可行), 污染知识库。

**置信度标注为何失效**: 事后给结论贴"低置信度"标签治不了病根——
污染发生在过程中, 不在结论处。真正的防御是**过程透明**: 每步决策留痕, 翻转可被检测。

## 二、核心机制: 决策日志四字段

任何探索性任务的决策条目, 必须记录四个字段:

```yaml
decision:
  conclusion: ""        # 结论 (该步骤认为什么)
  evidence: ""          # 依据 — 必须是观测, 不是叙事 (命令输出/文件内容/实测数值)
  assumption: ""        # 假设 — 自圆其说的源头, 必须显式写出
  verification: ""      # 验证 — 如何证伪; 没有验证方法 = 这是叙事不是结论
```

**判据**:
- evidence 不是观测 → 降级为假设
- assumption 为空 → 大概率隐藏了自圆其说的假设
- verification 为空 → 该"结论"不可采信, 标记为叙事

## 三、翻转预警

同一决策点出现反向结论(可行→不可行)时:
1. 累计 1 次 → 标记"不稳定"
2. 累计 2 次 → 警告"可能陷入自圆其说"
3. 累计 3 次 → 冻结该决策, 强制回到目标层重新审视

**局限(诚实声明)**: 纯词对匹配无法区分"讨论正反"与"时间线翻转"。
本扩展的价值依赖决策日志结构化 (字段格式), 而非文本扫描。

## 四、两阶段归档工作流

```
归档指令发出前: 记忆备份在 WSL 内 (活跃区, 可回滚)
归档指令发出后: WSL 内记忆 → 压缩 (tar.gz) → 扔到 Windows D 盘
```

- 实现: `scripts/archive_wsl.sh` (WSL压缩 → D盘/archive/记忆快照/)
- 纪律: 跨 /mnt 桥禁止 rsync 大目录复制, 用 tar 原地压缩再移
- 坑: symlink (bridge) 无同步逻辑, 不是副本; 回滚必须依赖真压缩包

## 五、与 sanyuan 的关系

| sanyuan 模块 | 本扩展的对应 |
|--------------|-------------|
| meta-normalization (元归一化) | 决策日志的"依据必须是观测" = 元信息空间 M 的过滤 |
| hu-normalization (互归一化) | 翻转预警 = 关系空间 H 的一致性检查 |
| archive-ingestion (归档迁移) | 两阶段归档 = 归档前决策留痕, 归档后方案入迁移队列 |
| think-before-responding (三思) | 决策四字段 = 独立研判的输出契约 |

**核心对应**: 自圆其说 = 归一化失败 (信息进入 M/H 空间时未过滤叙事层)。
过程透明 = 归一化前的输入契约。

## 六、触发条件

- 探索性/逆向/反编译类任务 (结论可能反复翻转)
- 任何"先探索后下结论"的工作流
- 需要跨 session 保持决策可追溯的项目

## 七、边界 (不做的事)

- 不替代 conscious/unconscious 注意力引擎
- 不替代 archive-ingestion (归档后路由)
- 不承诺文本扫描能检测语义翻转 (依赖结构化输入)
